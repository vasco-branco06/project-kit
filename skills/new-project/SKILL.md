# new-project

Talk to the owner in the language they use. Ask one question per turn, with your recommended answer and a one-line reason. Never write a file the owner has not approved.

## Steps

1. Check the target folder. Empty means it holds nothing but `.git`. If it is not empty, stop and offer the `organize` skill instead. Write nothing.
2. Ask the project type: research, academic, code or general. Recommend the one closest to the final deliverable. An invalid answer gets one clarifying question; with no type, write nothing.
3. Ask the language of the work output. The filled files, fixed template text included, are written in it; file names stay in English. Two markers stay literal English because `run` and `check_kit.py` search for them: `n/a until the plan` and the `<!-- read-order -->` line.
4. Ask the owner, one item per turn, for the objectives, what counts as done, and any rules or tests they want. If the objectives or the done checks are still missing after one re-ask with a recommended answer, do not go on. The coordinator decides everything else and logs it.
5. For code projects, record the stack the owner already names (language and runtime, framework or libraries, test tool and command, linter and formatter, package manager, hosting or run target); versions and reasons come later from `run` section 3, with the researcher. Add `ui-context.md` only when there are screens or a visual deliverable.
6. For research and academic projects also ask the citation style (the source log needs it); for academic ones also the deliverable format, page limit and teacher guide, one per turn.
7. Run `folder-plan` (after step 6). Go 1 is its plan, which includes the mandatory agents; nothing is written before it. After go 1 you create the folders (`folder-plan` only returns the plan) and offer `git init` without a remote for code. "Decide and go" skips neither go (list in `run` section 4).
8. Build each file from `${CLAUDE_PLUGIN_ROOT}/templates/core` plus `${CLAUDE_PLUGIN_ROOT}/templates/<type>` (a type file with the same path as a core file, for example the code `context/architecture.md`, replaces the core one; and `${CLAUDE_PLUGIN_ROOT}/templates/optional/ui-context.md` when it applies, written to `context/ui-context.md` with a ninth line for it added to the read order of `CLAUDE.md`). Replace every placeholder in double braces with real content, except in `context/specs/_unit-template.md`, which stays unfilled because `run` copies it for each unit: `{{DATE}}` is today, `{{MODEL_NAME}}` the running model's name, `{{PROJECT_NAME}}` the folder name unless the owner says otherwise, `{{STYLE_GUIDE}}` the official style guide of the language named in step 5, or `n/a until the plan` when no language is named, `{{DECIDED_BY}}` owner or coordinator; anything not known yet (stack record, commands, run-the-app and first-unit fields, `{{INVARIANTS}}`, `{{COMPONENTS}}`, `{{DATA_FLOW}}`, `{{CONSTRAINTS}}`) is `n/a until the plan`, and `run` fills it (its section 3); outside code the invariants are `[soft]` (for example page count, every citation has a reference); `{{GOAL}}`, `{{DONE_CHECKS}}`, `{{SCOPE_IN}}`, `{{SCOPE_OUT}}`, come from the step 4 answers; `{{OWNER_RULES}}`, `{{OWNER_TESTS}}`, `{{DELIVERABLE_FORMAT}}` (the step 6 answer), `{{PAGE_LIMIT}}` and `{{TEACHER_GUIDE}}` are "none given" when the owner has none; `{{PROJECT_TYPE}}` and `{{WORK_LANGUAGE}}` are the step 2 and 3 answers, `{{CITATION_STYLE}}` the step 6 answer (`n/a` for other types, where the citation style line of `context/source-log.md` is dropped), `{{STANDARDS_FILE}}` the standards file named below, and you fill every `{{DECISION_*}}` and `{{FIRST_DECISION_TITLE}}` by the first-entry rule below; when `ui-context.md` is added, its `{{TOKEN_*}}`, `{{TYPOGRAPHY}}`, `{{LOOK_AND_TONE}}`, `{{SPACING_AND_RADIUS}}`, `{{LAYOUT_PATTERNS}}` and `{{COMPONENTS_AND_ICONS}}` are `n/a until the plan` (or "none given"); `{{CURRENT_PHASE}}` is "setup done, waiting for the first run", `{{NEXT_STEPS}}` is "run /project-kit:run", and the first decision entry (titled project type, language and citation style) has the owner's request as context, what was offered as options, the chosen value as decision, one line of trade-offs, and n/a in every other field. Use `writing-and-evidence-standards.md` (a core file) for research, academic and general, and `code-standards.md` for code; for code, do not copy the writing standards. `{{STANDARDS_FILE}}` names whichever applies.
9. After go 1 copy the mandatory agents (`${CLAUDE_PLUGIN_ROOT}/templates/core/CLAUDE.md`) from `${CLAUDE_PLUGIN_ROOT}/templates/agents/` into `.claude/agents/` unchanged (`model: inherit` is only a fallback; the coordinator passes the model per unit on every call). Other roles are proposed in the run plan. The evaluator keeps the model of its template; write agent files with a shell command if a write hook removes the model line.
10. Show all the files together as one list (for code including `${CLAUDE_PLUGIN_ROOT}/templates/code/context/specs/` with first-unit fields `n/a until the plan`, and the dotfiles `.gitignore` (it ignores `.worktrees/`) and `.gitattributes` (LF, which frozen hashes need) from `${CLAUDE_PLUGIN_ROOT}/templates/core/`; other types get neither; the first `context/decisions.md` entry is among them) and ask once for go 2 ("go to the files"); show any file in full if the owner asks. Write them only after go 2. If a placeholder is still unfilled, say so and do not write; `n/a until the plan` counts as filled, and `context/specs/_unit-template.md` is the one file that keeps its placeholders.
11. Run `python -I "${CLAUDE_PLUGIN_ROOT}/test/check_kit.py" <new folder>` when Python is available and report the result. If it is not available, say that the check was skipped. If an agent file lost its `model` line, a write hook removed it: add it back with a shell command.
12. Tell the owner to start work with `/project-kit:run`.

## Rules

- Never delete anything. Never write secrets, keys or real personal data; use placeholders.
- On a write error, stop, list the files written and the ones pending, and ask how to go on.
- The always-ask list is the last sentence of the "Who decides" section in `${CLAUDE_PLUGIN_ROOT}/templates/core/CLAUDE.md` (commit, push, publication, spending, tool install, other model family, data leaving the machine, scope change).
